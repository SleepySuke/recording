# T13：E2E golden 比对测试

> 依赖：T12 · 预算：1.25h · 状态：**未开始**

**设计依据**：测试设计 §5（预期-真实比对机制、E2E 用例、结果目录约定）、§2（E2E 替身：Mock ASR 按种子注入、LLM 指向本地桩）；详设 §10 配置初值
**测试依据**：E2E-01～E2E-08；验收清单「异步与真实摘要」「重试、删除与恢复」对应条目

## 目标

`make e2e`：compose 起真实服务（种子注入的 Mock ASR + 本地 LLM 桩）→ 驱动 8 个场景 → 采集真实结果 → 与 golden 逐字段深度比对 → 输出 diff → 清理。

## 涉及文件

- Create：`e2e/runner_test.go`（或 `cmd/e2e`，实现时二选一：go test + build tag 优先）
- Create：`e2e/expected/E01…E08.json`（8 份 golden）
- Create：`e2e/actual/`、`e2e/diff/`（运行产物，Git 忽略 actual/diff）
- Modify：`Makefile`（`make e2e` 目标；并入 `make test` 全量）

## 交付接口

```text
e2e/
  expected/<case>.json   先行构造：HTTP 状态/业务码/status/attempt、状态序列、事件序列(event+attempt+error_code 按 event_seq)、
                          终态产物、数据库终态断言
  actual/<case>.json     采集：轮询 API + 直连测试库 + 过滤 logs/app.jsonl
  diff/<case>.txt        失败时字段级差异；保留现场（容器日志 + 数据卷）
忽略清单：ID、时间戳、耗时字段；顺序性字段（状态/事件序列）按序严格比对
```

E2E 种子机制：Mock ASR 的 DeterministicTranscriber 按 task_id 种子决定延迟/成败/文本（复用 T06 测试替身的生产可注入形态）；LLM 桩 = FakeLLM 以独立进程/端口运行（实现时选最简：go test 内起 httptest.Server 并把 LLM_BASE_URL 指过去，或 compose 侧注入）。

## 步骤

- [ ] 1. 先写 8 份 golden（E2E-01～08 场景见测试设计 §5.2 表：成功主链路 / 转写失败重试 / LLM 超时重试 / 重试冲突与不存在 / 处理中删除 / 重启恢复 / 并发上限 / 列表与状态汇总）。
- [ ] 2. 实现采集器：HTTP 驱动 + 轮询 + 直连测试库 + `jq`/Go 过滤 app.jsonl（`docker kill` 支持 E2E-06 的重启场景）。
- [ ] 3. 实现深度比对：忽略清单外逐字段相等；不一致输出 diff 文件并保留现场、返回非零。
- [ ] 4. 逐场景跑通并修正（先 E01，再其余）；`make e2e` 一条命令完成起栈→驱动→比对→清理。
- [ ] 5. `make test` 全量绿：单元恒跑、集成按 DSN、E2E 按 Docker，缺环境自动跳过并说明。
- [ ] 6. 提交：`test: add e2e golden comparison suite`。

## 完成标准

- [ ] 不变量巡检自动执行：测试库无孤儿任务、无重复 (task_id, event_seq)、无半删除状态（测试设计 §6）。
