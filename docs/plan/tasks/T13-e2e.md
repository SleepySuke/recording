（T06E 建立、各任务随任务落地）：**过程级套件 `e2e/` 已按用例交付深度验证**（E01 主链路、

1. **`make e2e` / `make test` 接线**：`make e2e` = 过程级 golden 套件（`go test ./e2e/
   -race`，需 `TEST_MYSQL_DSN`，未设跳过并提示，与集成层同风格）；`make test` 三层语义
   （单元恒跑；DSN 设定时集成 + E2E 逐层执行）。
2. **compose 全栈 golden 冒烟（单例 E-COMPOSE）**：`make build` 镜像 + compose 起栈 →
   宿主经发布端口驱动真实容器完整用户旅程（上传 → done → 详情）→ 采集 compose 应用库
   事件链、命名卷内录音文件、宿主 `./logs/app.jsonl` 事件镜像 → 与 `expected/E-COMPOSE.json`
   深度比对。`E2E_COMPOSE=1` 显式开启（常规套件不要求 Docker）。
3. **不变量巡检（compose 限定本任务行）**：应用库为真实数据（不 TRUNCATE、不做全表
   table_counts 断言），只断言本任务无重复 (task_id, event_seq) 与事件链从 1 连续。

明确不做（控制范围）：八个用例经 compose 重驱（深度验收已在过程级）；compose 内 docker-kill
重启演练（E06 与 T10 的 kill -TERM 已覆盖）；E-COMPOSE 之外的 compose golden 文件。

## 替身注入（不改 .env）

- 容器 LLM → 宿主 FakeLLM：临时 compose override 仅覆写 `LLM_BASE_URL=http://host.docker.internal:<port>/v1`
  （Docker Desktop 将其转发到宿主回环；起跑前容器内 wget 预检 + golden 中确定性摘要双重验证）。
